# Causal Rolling Detector — Initial Results

## Run provenance

Results were generated by GitHub Actions from the pinned Microsoft Cloud Monitoring Dataset using the prepared modelling view. The evaluation used per-series chronological 60/20/20 train/validation/test partitions.

The causal rolling detector used:
- 60 preceding observations per window;
- a minimum of 20 non-missing historical observations;
- a fixed threshold of 3.5 for the primary comparison;
- a gap reset when an interval exceeded three times the median positive interval estimated from the training prefix only;
- per-series threshold selection on validation data only for a separate comparison.

The current observation was excluded from its own reference window. Test labels were not used for threshold selection.

## Test-set coverage

| Measure | Causal rolling detector |
|---|---:|
| Test rows | 45,051 |
| Scored rows | 41,313 |
| Unscored warm-up/gap/zero-scale rows | 3,736 |
| Original missing-value rows | 2 |
| Scoring coverage | 91.70% |
| Positive labels among scored rows | 576 |
| Positive labels in unscored rows | 0 |

Coverage is higher than the static training-distribution baseline (91.70% versus 84.74%). The rolling detector scored observations in several series whose static training scale was zero, but it still left some rows unscored during warm-up or after temporal gaps.

## Fixed-threshold comparison

Both methods use the predeclared threshold of 3.5.

| Test metric | Static robust z-score | Causal rolling detector |
|---|---:|---:|
| True positives | 319 | 301 |
| False positives | 2,594 | 1,923 |
| False negatives | 208 | 275 |
| Precision | 10.95% | 13.53% |
| Recall on scored rows | 60.53% | 52.26% |
| F1 on scored rows | 18.55% | 21.50% |
| Recall counting unscored positives as misses | 55.38% | 52.26% |
| F1 counting unscored positives as misses | 18.29% | 21.50% |

At the fixed threshold, the rolling detector has higher precision and F1, and fewer false positives, but lower recall. It is not uniformly better: it misses more labelled anomalies while producing fewer false alarms.

## Validation-selected threshold comparison

Each series' threshold was selected by validation F1 over the predeclared grid. The test partition was not used for selection.

| Test metric | Static validation-tuned | Rolling validation-tuned |
|---|---:|---:|
| True positives | 335 | 278 |
| False positives | 2,572 | 2,454 |
| False negatives | 192 | 298 |
| Precision | 11.52% | 10.18% |
| Recall on scored rows | 63.57% | 48.26% |
| F1 on scored rows | 19.51% | 16.81% |
| Recall counting unscored positives as misses | 58.16% | 48.26% |
| F1 counting unscored positives as misses | 19.24% | 16.81% |

For the rolling detector, 20 series received a validation-selected threshold, 36 fell back because validation contained no positive labels, and four fell back because no validation rows were scoreable. The validation-selected thresholds did not generalise as well as the fixed 3.5 threshold on this test partition.

## Interpretation

The fixed-threshold rolling detector is a useful candidate: it increases scoring coverage and improves precision and F1 relative to the static fixed-threshold baseline, at the cost of recall. However, the validation-tuned rolling comparison performs worse than both the rolling fixed-threshold result and the static validation-tuned result. This is evidence that the current per-series validation F1 selection procedure is not reliably transferring to the held-out period for this detector.

The experiment does not establish production alert quality. Point-level metrics do not measure alert fatigue, event matching, detection delay, or operator usefulness. Per-series error analysis and event-level evaluation remain necessary before selecting a preferred detector.

## Reproduction

Run:

```bash
python -m cloudpulse.data.evaluate_microsoft_baseline
```

The generated artifact is `microsoft-cloud-monitoring-causal-rolling` in the GitHub Actions workflow. Default rolling parameters can be changed using `--rolling-window`, `--rolling-min-periods`, and `--max-gap-factor`.
