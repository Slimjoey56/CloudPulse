# Exploratory Findings — Microsoft Cloud Monitoring Dataset

## Reproducibility

These findings were generated by the `cloudpulse.data.explore_microsoft` command in GitHub Actions from the pinned Microsoft dataset snapshot `6a07a53c2fac495fb6831811df4c980d6c04bd10`. The command applies the documented modelling-view policy before computing per-series summaries. The JSON output is retained as the `microsoft-cloud-monitoring-exploration` workflow artifact.

## Sampling frequency and coverage

- 11 series have a median observed interval of 60 seconds.
- 49 series have a median observed interval of 3,600 seconds.
- Prepared series lengths range from 168 to 20,160 rows.
- The interval-gap flag is defined as an interval greater than 1.5 times the series-specific median interval. The 29 flags are prompts for inspection, not proof of data loss.

## Missing measurements

All 42 missing numeric measurements occur in three application crash-rate series:

| Series | Missing measurements |
|---|---:|
| application-crash-rate-1/app1-04 | 5 |
| application-crash-rate-1/app1-05 | 11 |
| application-crash-rate-1/app1-06 | 26 |

These observations remain in the prepared frame as missing values. No imputation has been applied.

## Label prevalence varies substantially

The share of anomaly-labelled points varies by series. Among series with positive labels, the observed range is approximately 0.038% to 25.575%. Six series have no anomaly-labelled points in this snapshot. These differences make a single pooled evaluation potentially misleading. Future anomaly-detection experiments should report per-series metrics and clearly state how zero-positive series are handled.

## Implications for modelling

1. Establish chronological train, validation, and test windows separately for each series.
2. Keep the six no-positive-label series available for false-positive and alert-volume analysis, but do not calculate recall or F1 as if positive examples exist.
3. Report metrics per series and provide a carefully defined aggregate in addition; do not pool raw measurement values across different metrics.
4. Treat the 42 missing measurements explicitly. Any imputer must be fitted on training data only.
5. Inspect the 29 flagged intervals and define how gaps affect window construction before model fitting.
6. Define point-to-event conversion and event matching before reporting event-level precision or recall.

## Scope limits

This report is descriptive. It does not establish stationarity, seasonality, causal relationships, predictive signal, model performance, CPU/memory behaviour, or capacity forecasts. Those require separate analysis and appropriate data.
